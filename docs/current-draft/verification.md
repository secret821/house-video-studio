# 当前草稿保存/查询与原片保留验收

状态：本轮代码与隔离验收完成，未单独发布公网。MySQL接入由并行任务统一收口；数据库迁移/发布状态见[MySQL验收](../mysql-integration/verification.md)。本记录不把本地文件模式的通过结果冒充公网MySQL验收。

用户确认的行为是：上传只一次，保存草稿只提交JSON和素材引用；进入页面先查询，有当前草稿就赋值；每账号/模式仅保留当前一份，视频也保留到新建或移除。该要求替换此前仅浏览器草稿和原片两小时清理规则。

## 实现与边界

- `server-draft-api.ts`共用既有fetch/Zod及会话身份头，GET返回`{project,revision}`，POST只传元数据与预期revision；串行写入、确认内容去重，Hook合并排队编辑。失败提示未保存，旧revision不能覆盖新建或另一页面更新。
- 移除原先上传成功后整段视频GET、IndexedDB备份和以此阻塞编辑的路径。旧浏览器JSON只在服务器无草稿时读取；不清空尚未迁移的旧IndexedDB。之前已缺失的原片不能伪报恢复。
- 原片在`data/current/<workspace>/uploads`，当前草稿在服务器（公网MySQL；无DB本地文件模式为账号drafts）。新建/移除后只回收原草稿已引用、两模式均不再引用且无在用任务/媒体流的素材。未认领旧上传不盲删，仍计入配额。
- 启动先将旧temporary中的账号uploads同卷rename到稳定目录，再移除临时目录；同名冲突/符号链接停止处理，保留原文件。元数据保存不读取、下载或复制视频内容。合法临时准备结果被草稿引用时也以rename保留，inode不变；其余准备缓存、任务和成片仍临时。
- 账号5GiB默认上限合计稳定和临时目录，磁盘预留1GiB、媒体单槽、任务/流式保护、Host/Origin与账号隔离保持。现有付费禁用、主动原声字幕规则未改变。

本线程自有改动与共享入口范围记录在`artifacts/server-draft-2026-11-03/task-scope.json`。MySQL连接、账号仓储、SQL、数据库仓储及其迁移/测试由另一任务负责；共享index/video-edit入口中的DB包装不算本线程自有实现。模板字体、OCR等并行改动不计本线程验收。
