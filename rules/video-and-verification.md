# 媒体规则与交付验证

- 免费实拍默认封面在最前，1.2 秒、可配置 0.5～10 秒；随后完整播放真人开场与房屋讲解。预览、MP4、poster 和独立封面保持一致。
- 实拍封面版本由coverStyle（new/original）控制，缺失默认new；模板区只显示两张模板卡片，封面版本在“切换封面样式”弹窗里用带参考图的勾选项切换；切换同步更新模板参考图、实时预览、独立封面及MP4，原版保留。新版人物封面留出顶部空间并在右侧红色信息区排标题；新版房屋封面使用避开水印的叠层红色标题卡，标题在卡内上下居中，渐变流光详情卡内只突出两项房源信息且文字上下居中，其余要点放在艺术描边总价下方，后续房屋素材可显示双照片卡片。所有动画按帧驱动，文字与图片仅取当前草稿。
- 以下旧版封面规则适用于original：经典实拍默认首份房屋素材，保留原描边字；杂志留白默认口播开场第0帧，人物封面标题与浅金副标题按2026-11-04最新要求缩小并下移，保证三列缩略图的居中裁切不会截断标题；原版经典房屋封面的标题在既有高度适当加粗加大，并核对同一缩略图裁切，房源要点位置不变；按2026-11-04最新要求取消经典实拍右下价格卡，改为画面中部居中的较亮珊瑚红总价文字，附加特点放在总价下方，联系文字放在底部；杂志片内仍采用橙金色正体衬线字、深色描边与下划线；杂志片内装饰标题同步橙金衬线风格，原声字幕保持经典可读样式，不加文字底色或顶部边框。第一套参考图以虚构人物口播首帧作示意，第二套以房屋作示意；两者可选其他封面来源，冻结且静音，预览、独立封面与两种MP4路径一致。旧草稿缺失videoTemplate时为classic；新模板为editorial，照片模式同步。已有项目切换时房源资料/素材共用，videoTemplate与模板默认coverSource同步：经典House、杂志Opening；封面排版、片内文案和片尾由模板驱动，字幕文字、声音和时序保留；新旧模板成片按各自模板区分缓存。上一版可继续下载并标明其模板，预览始终使用当前配置实时渲染，旧成片单独播放下载，不替代实时预览。共享模板组件改动须重建两套预构建视频包。片尾保留克制版式，字段共用。
- 默认保留两段原声，音乐低音量铺底；保留讲解时不能为转场剪短或重叠人声。照片人物开场直接上传，不恢复生成入口。
- 实拍与照片模式共用左上角淡珊瑚橙色粗斜体衬线艺术字水印（浅色细描边与阴影），默认“青连实拍”，单行最多20字，可修改、留空关闭。封面、全片预览、原生图层合成、浏览器渲染和照片分段导出使用同一水印组件；水印不得改变音频或时长，改文字/关闭必须使相关成片与全部照片分段缓存失效。
- 竖屏优先避让微信手机播放控件：片内水印与经典封面水印置于顶部状态栏下方；按2026-11-07用户要求，杂志留白人物封面单独回退到11月6日调整前的水印、标题、价格条和底部文字位置；封面底部联系文字、免责声明、片内房源信息与原声字幕保持在底部正文和操作区上方。照片模式横屏的字幕与底部信息栏不得互相覆盖。具体位置须以实际竖屏帧和微信端截图复核，不把单一设备截图当成所有微信机型的固定安全区。
- 上传只收原片并在轻量探测槽校验元数据，不转码、不抽帧、不计算整片摘要。生成时在重型媒体槽串行准备原片，单份15分钟截止；只更新渲染快照，不改变原声时长与用户片段范围。原片预览受浏览器编解码支持限制，应明确提示可生成后播放。
- 无画面重叠的纯视频时间线使用同模板稀疏透明动画帧＋有背压的1080P原生合成；其他时间线沿用全帧浏览器渲染。原声按相同帧时序串联，不能降低分辨率或重叠讲解。原片、音频与封装继续使用固定Remotion FFmpeg；管理员可通过`pnpm setup:compositor`安装固定SHA256的独立叠加运行时（`.runtime/compositor`或`STUDIO_COMPOSITOR_DIR`），只接收生成的原始YUV/PNG，禁止读取上传的编码媒体或外部URL。不得替换系统FFmpeg；未安装或校验失败沿用兼容路径，不在请求内自动安装。
- Remotion 动画一律帧驱动。迁移 Next 不能改变视频模板、分段缓存身份、原声、素材或用户草稿。
- `pnpm dev` 与 `pnpm start` 都使用自定义本地服务；生产先 `pnpm build`，不能直接 `next start` 绕开本机 API 和安全中间件。构建输出为 `.next/`，不是 dist；不启用 static export 或 standalone。
- 宝塔小内存部署同时执行 `pnpm build:video` 并发布 `.video-bundles/`；开启 `PREBUILT_VIDEO_BUNDLES=1` 时源码摘要须匹配，不能回退为运行时编译。部署步骤与资源限制见 `deploy/README.md`。
- 完成交付前运行 `pnpm lint`、`pnpm format:check`、`pnpm typecheck`、`pnpm build`、`pnpm test`。构建和开发使用不同 Next 输出目录，避免相互覆盖。
- 实际验证 `/`、`/video-edit` 直达与刷新、页面互跳、静态资源、`/api` 统一 envelope 的成功和 JSON 错误、原有草稿读取、桌面/窄屏预览以及本地导出 MP4 的编码、画幅、时长和画面。验收不得发付费请求或覆盖已有草稿。新协议发布时 Next 与 Express 同版本部署并一起回滚，镜像必须使用本轮 `pnpm-lock.yaml` 重建。
- 验证记录写 `verification.md`，明确已验证和未覆盖项；只在用户明确要求时发布公网。
- 当前草稿保存/查询只传账号元数据和媒体引用，不能回下载原片或等待浏览器Blob备份。原片在稳定账号uploads，引用的临时准备结果通过同卷rename保留；准备缓存仍临时。验证须覆盖刷新、新浏览器、真实重启、JSON体积与无备份GET，以及新建/移除的双模式引用和在用保护；过时revision不能恢复已新建的项目。
